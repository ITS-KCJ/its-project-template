Conceito

Duas coisas que trabalham juntas

GSD /gsd-*

Framework de engenharia de contexto no Claude Code. Quebra o trabalho em milestones → fases → tarefas e conduz cada fase com planejamento, execução e verificação. Evita que a IA se perca em sessões longas.

its-project-template

Repositório template no GitHub. Todo projeto novo nasce já com documentação (onboarding, runbooks, ADRs), governança de PR e as convenções ITS prontas. A equipe só preenche os placeholders.

◆
O GSD diz como construir. O template garante que todo projeto começa padronizado e fácil de dar suporte.
Passo 1 · sempre antes de tudo

Escolha o nível pelo risco

Não use o ciclo completo para tudo. Decida primeiro o tamanho do risco.

Nível 1 · Trivial

typo, config, 1 arquivo

/gsd-fast ou edição direta

Nível 2 · Manutenção

bug, feature pequena

/gsd-quick ou /gsd-debug

Nível 3 · Estrutural

banco, RBAC, módulo novo

ciclo completo (próximo slide)

Regra fixa: migração de banco nunca é nível 1. Em dúvida entre 2 e 3, comece no 2 e escale.

Passo 2 · uma vez por projeto

Preparar o projeto

/gsd-new-project
projeto novo: cria roadmap, milestones e fases
ou
/gsd-map-codebase
projeto que já existe: mapeia o código e gera o contexto
+
/gsd-new-milestone
novo bloco de trabalho num projeto já preparado

Depois disso existe um roadmap em .planning/. O trabalho passa a ser feito fase a fase.

Passo 3 · nível 3

Ciclo de uma fase

A ordem é sempre esta. Cada passo só começa quando o anterior fecha.

discuss-phase
alinhar abordagem e decisões
→
plan-phase
plano executável: tarefas e dependências
→
execute-phase
implementa, commits atômicos
→
verify-work
confere que a fase entregou o prometido

UI

/gsd-ui-phase + /gsd-ui-review

Segurança

/gsd-secure-phase antes do ship

Faltou teste

/gsd-add-tests

Durante o trabalho

Comandos de apoio

/gsd-next

o que fazer agora

/gsd-progress

onde a fase/milestone está

/gsd-health

saúde geral do projeto

/gsd-resume-work

retomar de onde parou

/gsd-pause-work

pausar registrando o estado

/gsd-workstreams

trabalho paralelo no mesmo repo

Nunca abra duas sessões do Claude na mesma pasta. Para paralelo, use workstreams. Milestone fechado: /gsd-complete-milestone.

Passo 4 · vale para qualquer nível

Ordem de PR e GitHub HML-first

Branch  git checkout -b feat/nome-curto — nunca na main
Trabalhar — o ciclo GSD roda aqui, commits atômicos
Validar local — git diff --check + testes / lint / build
Homologação — deploy na VM .96 e validação real
Pull Request — PR para main, preencher o template. CI vermelho não é revisado
Review  /gsd-code-review — --comment posta os achados no PR
Merge — o owner faz o merge na main (/gsd-ship empacota)
Produção (só owner) — fase completa + gate validado + GO → deploy

Para fechar

Regras de ouro

  • HML-first — nada em produção sem homologação e sem GO do owner.
  • Nunca na main — sempre branch + PR. CI vermelho não é revisado.
  • Nível pelo risco — banco nunca é trivial.
  • Segredo nunca no código — placeholders em exemplos.
  • Português na doc, inglês no código — e sem travessão.
